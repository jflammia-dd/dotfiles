## What happened

### SEC-32487: Disable automatic CD for siem-entity-resolution-api

The goal was to constrain prod deployments to a single DC without monitor gates, matching the control Dynamic Deployments gives `deploy.yaml` services. Auto-CD via Conductor deploys to all DCs at once with the 45-minute per-DC gate, making manual staged rollouts awkward.

**PR #458494** (merged): Removed `staging` and `prod` from `topology.enabled` in `rapid.json`. This was based on the assumption that `topology.enabled` controls only Conductor auto-CD.

**Key finding:** `topology.enabled` gates both Conductor and manual `rapid release` through the same validation path in [`validation.go:47-52`](https://github.com/DataDog/dd-source/blob/main/domains/rapid/apps/rapid/cmd/release/pkg/validation.go#L47-L52). Removing `prod` made `deploy-prod.sh` fail with "env prod is not enabled." There is no `rapid.json` config that separates Conductor triggering from manual releases; both share the gate.

**Additional finding:** `staging` bypasses `topology.enabled` entirely. The validator unconditionally returns true for staging and dev regardless of the array contents. Removing `staging` from the array was a no-op.

**`--unsafe` flag:** Disables monitor gates in production only. It does not bypass the topology check. Confirmed by reading `rapid release --help` and the source.

**45-minute DC gate:** Hardcoded as `defaultDatacenterSleepTime = 2700` in [`helm.go:60`](https://github.com/DataDog/dd-source/blob/main/domains/api_platform/rapid/etc/delta_workflow_gen/pkg/dynamic/writer/helm/helm.go#L60). Cannot be configured via `rapid.json`. Only skippable via Mosaic Customized Tasks UI.

**PR #458777** (merged): Restored `prod` to `topology.enabled` so manual `rapid release --env prod` works again. `staging` was not restored (no-op).

**Current state of `rapid.json`:**
- `topology.enabled: ["prod"]`
- `gating.monitor.duration: 1` (effectively no-op cluster gate, from SEC-31820)
- `overrides.prod.deploymentStrategy: geometric_fast`

### Local deploy scripts

Three scripts exist locally, excluded from git via `.git/info/exclude`:

- `tools/deploy-staging.sh`: `rapid release --env staging`
- `tools/deploy-prod.sh`: `rapid release --env prod --branch main --datacenters us1.prod.dog --unsafe`
- `tools/deploy-prod-full.sh`: `rapid release --env prod --branch main --unsafe`

These are deliberately not in the repo per Clement Gaboriau Couanau's feedback (thin wrappers that go stale with CLI updates).

## What is not done

**Open:** The original goal (disable Conductor auto-CD for prod while keeping manual `rapid release` functional) is not achievable via `rapid.json` alone. A follow-up with the Rapid team is needed to find out if a Conductor-specific pause mechanism exists outside of `rapid.json`.

**Current behavior:** Conductor auto-deploys to prod on every merge to main using `geometric_fast`. Manual staged rollouts work via the local scripts above.
